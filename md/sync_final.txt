# ECS → COS 迁移方案（3台机器最终版）- 带Metrics监控

## 分区方案

| 机器 | 范围 | 说明 |
|------|------|------|
| 机器1 | 00-90 | 0-8 开头 |
| 机器2 | 90-96 | 9 开头前半 |
| 机器3 | 96-: | 9 开头后半 |

---

## 迁移脚本

### 机器1 脚本 (00-90)

```bash
#!/bin/bash
# machine1_00-90.sh - 机器1：0-8 开头

LOG_DIR="/var/log/juicefs"
FAILED_LIST="$LOG_DIR/failed_00-90.list"
METRICS_PORT=9567

mkdir -p $LOG_DIR
> $FAILED_LIST

echo "===== 机器1开始迁移 00-90 (0-8开头) $(date) =====" | tee -a $LOG_DIR/migration.log

# 启动 metrics 监控
(
    while true; do
        METRICS=$(curl -s http://127.0.0.1:$METRICS_PORT/metrics 2>/dev/null)
        if [ -n "$METRICS" ]; then
            COPIED=$(echo "$METRICS" | grep "juicefs_sync_copied" | awk '{print $2}' | head -1)
            SKIPPED=$(echo "$METRICS" | grep "juicefs_sync_skipped" | awk '{print $2}' | head -1)
            PENDING=$(echo "$METRICS" | grep "juicefs_sync_pending" | awk '{print $2}' | head -1)
            echo "[$(date '+%H:%M:%S')] 已复制: ${COPIED:-0} | 已跳过: ${SKIPPED:-0} | 待处理: ${PENDING:-0}"
        fi
        sleep 15
    done
) > "$LOG_DIR/metrics_00-90.log" 2>&1 &
METRICS_PID=$!
trap "kill $METRICS_PID 2>/dev/null" EXIT

# 错误监控
(
    tail -F $LOG_DIR/juicefs_00-90.log 2>/dev/null | while read line; do
        if echo "$line" | grep -qiE "error|fail|timeout"; then
            echo "$line" | grep -oE 's3://[a-zA-Z0-9._/-]+' >> "$FAILED_LIST"
        fi
    done
) &
TAIL_PID=$!

START_TIME=$(date +%s)

juicefs sync \
    --ignore-existing \
    --check-new \
    --threads 200 \
    --list-threads 50 \
    --start "00" --end "90" \
    --max-failure 10 \
    --verbose \
    --metrics "127.0.0.1:$METRICS_PORT" \
    s3://ecs-source/ \
    cos://cos-dest/ \
    2>&1 | tee "$LOG_DIR/juicefs_00-90.log"

EXIT_CODE=${PIPESTATUS[0]}
kill $TAIL_PID 2>/dev/null
kill $METRICS_PID 2>/dev/null

DURATION=$(($(date +%s) - START_TIME))
COPIED=$(grep -c "Copied data of" "$LOG_DIR/juicefs_00-90.log" 2>/dev/null || echo 0)
SKIPPED=$(grep -c -i "exist" "$LOG_DIR/juicefs_00-90.log" 2>/dev/null || echo 0)
ERRORS=$(grep -icE "error|fail" "$LOG_DIR/juicefs_00-90.log" 2>/dev/null || echo 0)

[ -f "$FAILED_LIST" ] && sort -u "$FAILED_LIST" -o "$FAILED_LIST"

echo "===== 机器1结束 $(date) =====" | tee -a $LOG_DIR/migration.log
echo "耗时: ${DURATION}秒 | 已复制: $COPIED | 已跳过: $SKIPPED | 错误: $ERRORS" | tee -a $LOG_DIR/migration.log
exit $EXIT_CODE
```

## 迁移完成后校验脚本

创建 `/opt/migration/verify.sh`：

```bash
#!/bin/bash
# verify.sh - 迁移完成后全面校验

# ============ 配置区域 ============
SRC_URL="s3://ecs-source/"
DST_URL="cos://cos-dest/"

LOG_DIR="/var/log/juicefs"
# =================================

echo "=========================================="
echo "  数据完整性校验"
echo "=========================================="
echo "源: $SRC_URL"
echo "目标: $DST_URL"
echo "时间: $(date)"
echo "=========================================="

echo ""
echo ">>> 开始校验（只检查不传输）..."
echo "注意: 校验时间可能较长，请耐心等待"
echo ""

# 全面校验所有文件（--check-all --dry）
juicefs sync \
    --check-all \
    --dry \
    --threads 50 \
    "$SRC_URL" \
    "$DST_URL" \
    2>&1 | tee "$LOG_DIR/verify.log"

EXIT_CODE=${PIPESTATUS[0]}

echo ""
echo "=========================================="
echo "  校验结果"
echo "=========================================="

# 统计结果
CHECKED=$(grep -c "Checked" "$LOG_DIR/verify.log" 2>/dev/null || echo 0)
MISMATCH=$(grep -c -i "NOT equal\|mismatch" "$LOG_DIR/verify.log" 2>/dev/null || echo 0)
FAILED=$(grep -c -i "check.*fail\|failed" "$LOG_DIR/verify.log" 2>/dev/null || echo 0)

echo "校验完成的文件: $CHECKED"
echo "不匹配的文件: $MISMATCH"
echo "校验失败: $FAILED"

if [ $EXIT_CODE -eq 0 ]; then
    echo ""
    echo "✓ 校验通过！所有文件完整性确认"
else
    echo ""
    echo "✗ 校验发现问题，请查看日志: $LOG_DIR/verify.log"
    grep -iE "NOT equal|mismatch|failed" "$LOG_DIR/verify.log" | head -20
fi

echo "=========================================="
```

## 执行步骤

### 1. 迁移

```bash
# 机器1
nohup /opt/migration/machine1_00-90.sh > /var/log/juicefs/machine1.out 2>&1 &

# 机器2
nohup /opt/migration/machine2_90-96.sh > /var/log/juicefs/machine2.out 2>&1 &

# 机器3
nohup /opt/migration/machine3_96-99.sh > /var/log/juicefs/machine3.out 2>&1 &
```

### 2. 查看进度

```bash
tail -f /var/log/juicefs/metrics_*.log
```

### 3. 迁移完成后校验

```bash
# 校验所有文件（只检查不传输）
/opt/migration/verify.sh
```

---

## 关键参数说明

| 参数 | 作用 |
|------|------|
| `--ignore-existing` | 已存在跳过 |
| `--check-new` | 新传输的文件自动校验（校验失败会重传） |
| `--check-all` | 校验所有文件（用于校验脚本） |
| `--dry` | 只校验不传输 |

---

## --check-new 行为总结

| 场景 | 是否校验 |
|------|---------|
| 新传输的文件 | ✅ 校验，失败会重传 |
| 已存在的文件 | ❌ 不校验 |
| 中断后续传 | 只校验新传输的部分 |

**因此迁移完成后务必运行 `verify.sh` 做全面校验！**
