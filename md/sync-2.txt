# 单节点 JuiceFS Sync 测试方案（高并发版）

## 方案概述

- **目标**：单台机器验证 ECS → COS 数据迁移流程
- **数据规模**：100TB，约 7.01 亿文件
- **策略**：单节点高并发，全量处理（不按前缀区分）
- **原则**：准确优先，存在即跳过，简单可重跑

---

## 架构设计

| 项目 | 配置 |
|------|------|
| 机器 | 1 台 |
| 处理范围 | 全量（0-9 全部） |
| 日志位置 | /var/log/juicefs |

> 注意：缓存配置在对象存储同步场景中不适用，如需缓存请使用 juicefs mount 挂载后同步

**硬件要求**：
- 内存：64GB+（200 线程需要）
- 存储：日志目录剩余空间 > 100GB
- 网络：内网访问 ECS 和 COS，带宽充足

---

## 准备工作

```bash
# 创建必要目录
mkdir -p /opt/migration /var/log/juicefs

# 添加执行权限

# 检查系统限制
```

## 阶段一：小批量测试（验证流程）

先测试一个小范围（如前 10000 个文件），验证配置正确。

创建 `/opt/migration/test_small.sh`：

```bash
#!/bin/bash
# test_small.sh - 小批量测试，验证配置

LOG_DIR="/var/log/juicefs"
FAILED_LIST="$LOG_DIR/failed_small.list"

mkdir -p $LOG_DIR
> $FAILED_LIST

echo "===== 小批量测试开始 $(date) =====" | tee -a $LOG_DIR/migration.log

# 使用 --limit 限制测试数量
juicefs sync \
  --ignore-existing \
  --threads 200 \
  --list-threads 50 \
  --limit 10000 \
  --max-failure 5 \
  --no-https \
  s3://ecs-source/ \
  cos://cos-dest/ 2>&1 | tee $LOG_DIR/juicefs_small.log

EXIT_CODE=$?

# 统计结果
echo ""
echo "--- 测试结果统计 ---"
copied=$(grep -c "Copied" $LOG_DIR/juicefs_small.log 2>/dev/null || echo 0)
skipped=$(grep -c "exist" $LOG_DIR/juicefs_small.log 2>/dev/null || echo 0)
errors=$(grep -icE "error|fail" $LOG_DIR/juicefs_small.log 2>/dev/null || echo 0)

echo "已复制: $copied"
echo "已跳过: $skipped"
echo "错误: $errors"

echo "===== 小批量测试结束 $(date)，退出码: $EXIT_CODE =====" | tee -a $LOG_DIR/migration.log
exit $EXIT_CODE
```

## 阶段二：全量迁移（测试通过后执行）

创建 `/opt/migration/migrate_all.sh`：

```bash
#!/bin/bash
# migrate_all.sh - 单节点全量迁移（100TB，7亿文件）

LOG_DIR="/var/log/juicefs"
FAILED_LIST="$LOG_DIR/failed_all.list"

mkdir -p $LOG_DIR
> $FAILED_LIST

echo "===== 单节点全量迁移开始 $(date) =====" | tee -a $LOG_DIR/migration.log
echo "数据规模: 100TB, 约7.01亿文件" | tee -a $LOG_DIR/migration.log

# 后台实时监控并提取错误
(
    tail -F $LOG_DIR/juicefs_all.log 2>/dev/null | while read line; do
        if echo "$line" | grep -qiE "error|fail|timeout"; then
            echo "$line" | grep -oE 's3://[a-zA-Z0-9._/-]+' >> "$FAILED_LIST"
            echo "[$(date '+%Y-%m-%d %H:%M:%S')] $line" >> "$FAILED_LIST.full"
        fi
    done
) &
TAIL_PID=$!

# 全量迁移 - 200线程高并发
juicefs sync \
  --ignore-existing \
  --threads 200 \
  --list-threads 50 \
  --max-failure 10 \
  --no-https \
  s3://ecs-source/ \
  cos://cos-dest/ 2>&1 | tee $LOG_DIR/juicefs_all.log

EXIT_CODE=$?
kill $TAIL_PID 2>/dev/null

# 去重失败列表
if [ -f "$FAILED_LIST" ]; then
    sort -u "$FAILED_LIST" -o "$FAILED_LIST"
    failed_count=$(wc -l < "$FAILED_LIST")
    [ "$failed_count" -gt 0 ] && echo "⚠️ 发现 $failed_count 个失败文件" | tee -a $LOG_DIR/migration.log
fi

echo "===== 全量迁移结束 $(date)，退出码: $EXIT_CODE =====" | tee -a $LOG_DIR/migration.log
exit $EXIT_CODE
```

## 断点续传方案（推荐用于大规模数据）

对于 7 亿文件的全量迁移，建议按批次执行，便于断点续传和监控。

创建 `/opt/migration/migrate_batch.sh`：

```bash
#!/bin/bash
# migrate_batch.sh - 分批迁移，支持断点续传

LOG_DIR="/var/log/juicefs"
BATCH_SIZE=${BATCH_SIZE:-1000000}  # 每批 100 万文件
FAILED_LIST="$LOG_DIR/failed_batch.list"

mkdir -p $LOG_DIR

# 获取已处理的文件列表（从日志中提取）
get_processed_files() {
    local log_file=$1
    if [ -f "$log_file" ]; then
        # 提取已复制和已跳过的文件
        grep -E "(Copied|exist)" "$log_file" 2>/dev/null | \
            grep -oE 's3://[a-zA-Z0-9._/-]+' | sort -u
    fi
}

echo "===== 分批迁移开始 $(date) =====" | tee -a $LOG_DIR/migration.log
echo "每批大小: $BATCH_SIZE 文件" | tee -a $LOG_DIR/migration.log

batch_num=0
total_copied=0
total_skipped=0

while true; do
    batch_num=$((batch_num + 1))
    BATCH_LOG="$LOG_DIR/juicefs_batch_${batch_num}.log"
    
    echo ""
    echo "--- 开始第 $batch_num 批 ---" | tee -a $LOG_DIR/migration.log
    
    # 执行当前批次
    juicefs sync \
      --ignore-existing \
      --threads 200 \
      --list-threads 50 \
      --limit $BATCH_SIZE \
      --max-failure 10 \
      --no-https \
      s3://ecs-source/ \
      cos://cos-dest/ 2>&1 | tee $BATCH_LOG
    
    batch_exit=$?
    
    # 统计本批次
    copied=$(grep -c "Copied" $BATCH_LOG 2>/dev/null || echo 0)
    skipped=$(grep -c "exist" $BATCH_LOG 2>/dev/null || echo 0)
    
    total_copied=$((total_copied + copied))
    total_skipped=$((total_skipped + skipped))
    
    echo "第 $batch_num 批完成: 复制 $copied, 跳过 $skipped" | tee -a $LOG_DIR/migration.log
    echo "累计: 复制 $total_copied, 跳过 $total_skipped" | tee -a $LOG_DIR/migration.log
    
    # 如果本批次处理少于 BATCH_SIZE，说明已经处理完
    if [ $((copied + skipped)) -lt $BATCH_SIZE ]; then
        echo "处理数量少于批次大小，判断为全部完成" | tee -a $LOG_DIR/migration.log
        break
    fi
    
    # 如果报错退出，暂停等待人工检查
    if [ $batch_exit -ne 0 ]; then
        echo "⚠️ 第 $batch_num 批异常退出，退出码: $batch_exit" | tee -a $LOG_DIR/migration.log
        echo "请检查日志: $BATCH_LOG" | tee -a $LOG_DIR/migration.log
        echo "修复后重新运行脚本会从断点继续" | tee -a $LOG_DIR/migration.log
        exit $batch_exit
    fi
    
    # 每 10 批暂停一下，避免日志过大
    if [ $((batch_num % 10)) -eq 0 ]; then
        echo "已处理 $batch_num 批，暂停 5 秒..." | tee -a $LOG_DIR/migration.log
        sleep 5
    fi
done

echo ""
echo "===== 分批迁移完成 $(date) =====" | tee -a $LOG_DIR/migration.log
echo "总计: 复制 $total_copied, 跳过 $total_skipped" | tee -a $LOG_DIR/migration.log
```

## 实时监控脚本

创建 `/opt/migration/monitor.sh`：

```bash
#!/bin/bash
# monitor.sh - 实时监控迁移进度

LOG_DIR="/var/log/juicefs"

while true; do
    clear
    echo "==== 单节点迁移监控 - $(date) ===="
    echo "数据规模: 100TB, 约7.01亿文件"
    echo ""
    
    total_copied=0
    total_skipped=0
    total_errors=0
    
    for log in $LOG_DIR/juicefs_*.log; do
        [ -f "$log" ] || continue
        
        name=$(basename $log .log)
        copied=$(grep -c "Copied" $log 2>/dev/null || echo 0)
        skipped=$(grep -c "exist" $log 2>/dev/null || echo 0)
        errors=$(grep -icE "error|fail" $log 2>/dev/null || echo 0)
        
        total_copied=$((total_copied + copied))
        total_skipped=$((total_skipped + skipped))
        total_errors=$((total_errors + errors))
        
        echo "[$name] 复制: $copied | 跳过: $skipped | 错误: $errors"
        
        # 显示最近处理的文件
        last_file=$(tail -2 $log 2>/dev/null | grep -oE 's3://[^[:space:]]+' | tail -1)
        [ -n "$last_file" ] && echo "  最近: $(basename $last_file)"
    done
    
    echo ""
    echo "--- 总计 ---"
    echo "已复制: $total_copied"
    echo "已跳过: $total_skipped"
    echo "错误: $total_errors"
    
    # 估算进度（基于7.01亿）
    total_processed=$((total_copied + total_skipped))
    if [ $total_processed -gt 0 ]; then
        percent=$(echo "scale=2; $total_processed / 701000000 * 100" | bc 2>/dev/null || echo "N/A")
        echo "进度: $total_processed / 701000000 ($percent%)"
    fi
    
    # 系统资源
    echo ""
    echo "--- 系统状态 ---"
    echo "内存使用: $(free -h | awk '/Mem/{print $3"/"$2}')"
    echo "内存使用率: $(free | awk '/Mem/{printf "%.1f%%", $3/$2 * 100}')"
    echo "CPU负载: $(uptime | awk -F'load average:' '{print $2}')"
    echo "磁盘空间: $(df -h /var | tail -1 | awk '{print $3"/"$2 " (" $5 ")"}')"
    
    # 待重试失败文件统计
    echo ""
    for failed in $LOG_DIR/failed_*.list; do
        [ -f "$failed" ] || continue
        count=$(wc -l < "$failed" 2>/dev/null || echo 0)
        [ "$count" -gt 0 ] && echo "待重试: $(basename $failed) 有 $count 个"
    done
    
    echo ""
    echo "按 Ctrl+C 退出"
    sleep 30
done
```

## 失败重试脚本

创建 `/opt/migration/retry_failed.sh`：

```bash
#!/bin/bash
# retry_failed.sh - 重试失败的文件

FAILED_LIST=${1:-""}
LOG_DIR="/var/log/juicefs"

if [ -z "$FAILED_LIST" ] || [ ! -f "$FAILED_LIST" ]; then
    echo "用法: $0 <失败列表文件>"
    echo "示例: $0 /var/log/juicefs/failed_all.list"
    echo ""
    echo "可用的失败列表:"
    ls -la $LOG_DIR/failed_*.list 2>/dev/null || echo "  无"
    exit 1
fi

retry_count=$(wc -l < "$FAILED_LIST")
echo "开始重试 $retry_count 个失败文件..."

RETRY_LOG="$LOG_DIR/retry_$(date +%Y%m%d_%H%M%S).log"
STILL_FAILED="$LOG_DIR/still_failed_$(date +%Y%m%d_%H%M%S).list"
> "$STILL_FAILED"

success=0
failed=0
batch=0

while IFS= read -r object; do
    [ -z "$object" ] && continue
    
    batch=$((batch + 1))
    echo "[$batch/$retry_count] 重试: $object"
    
    # 提取文件名用于 include
    filename=$(basename "$object")
    
    if juicefs sync \
        --ignore-existing \
        --threads 10 \
        --include "$filename" \
        --max-failure 1 \
        s3://ecs-source/ \
        cos://cos-dest/ 2>&1 | grep -q "Copied"; then
        
        echo "  ✓ 成功"
        ((success++))
    else
        echo "  ✗ 仍然失败"
        echo "$object" >> "$STILL_FAILED"
        ((failed++))
    fi
    
    # 每 100 个暂停一下
    if [ $((batch % 100)) -eq 0 ]; then
        echo "已处理 $batch 个，暂停 2 秒..."
        sleep 2
    fi
done < "$FAILED_LIST"

echo ""
echo "===== 重试完成 ====="
echo "成功: $success"
echo "仍然失败: $failed"
[ "$failed" -gt 0 ] && echo "列表: $STILL_FAILED"
```

## 抽样验证脚本

创建 `/opt/migration/verify_sample.sh`：

```bash
#!/bin/bash
# verify_sample.sh - 抽样验证（适合大规模数据）

SAMPLE_SIZE=${1:-1000}  # 默认抽样 1000 个
echo "===== 抽样验证 $(date) ====="
echo "抽样数量: $SAMPLE_SIZE"

# 1. 从源端随机抽样
echo ""
echo "--- 从源端抽样 $SAMPLE_SIZE 个文件 ---"

# 使用 juicefs sync 列举并随机抽样
sample_files=$(juicefs sync --dry-run --list-only s3://ecs-source/ /tmp/ 2>/dev/null | shuf -n $SAMPLE_SIZE)

if [ -z "$sample_files" ]; then
    echo "无法获取源端文件列表，请检查权限"
    exit 1
fi

echo "获取到 $(echo "$sample_files" | wc -l) 个样本"

# 2. 检查目标端是否存在
echo ""
echo "--- 检查目标端是否存在 ---"

found=0
not_found=0
checked=0

while IFS= read -r file; do
    [ -z "$file" ] && continue
    
    checked=$((checked + 1))
    filename=$(basename "$file")
    
    # 检查目标端是否存在
    if juicefs sync --dry-run --list-only --include "$filename" cos://cos-dest/ /tmp/ 2>/dev/null | grep -q "$filename"; then
        found=$((found + 1))
    else
        not_found=$((not_found + 1))
        [ $not_found -le 10 ] && echo "  未找到: $filename"
    fi
    
    # 每 100 个显示进度
    if [ $((checked % 100)) -eq 0 ]; then
        echo "  已检查: $checked, 找到: $found, 未找到: $not_found"
    fi
done <<< "$sample_files"

echo ""
echo "--- 验证结果 ---"
echo "总样本: $checked"
echo "找到: $found"
echo "未找到: $not_found"

if [ $checked -gt 0 ]; then
    accuracy=$(echo "scale=2; $found / $checked * 100" | bc 2>/dev/null || echo "N/A")
    echo "准确率: $accuracy%"
    
    if [ $(echo "$accuracy >= 99" | bc 2>/dev/null || echo 0) -eq 1 ]; then
        echo "✓ 验证通过"
    else
        echo "✗ 验证未通过，建议检查未找到的文件"
    fi
fi

echo ""
echo "===== 验证完成 ====="
```

## 关键参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `--threads` | 200 | 并发传输线程数 |
| `--list-threads` | 50 | 并发列举文件线程数 |
| `--ignore-existing` | ✅ | 目标存在即跳过，保证幂等性 |
| `--max-failure` | 10 | 连续 10 次失败即退出 |
| `--no-https` | ✅ | 不使用 HTTPS（内网环境） |
| `--limit` | 数量 | 限制处理的文件数量 |
| `--start` / `--end` | 范围 | 按 key 范围筛选 |
| `--exclude` / `--include` | 模式 | 按模式排除/包含文件 |
| `--bwlimit` | Mbps | 带宽限制（0=不限） |
| `--worker` | 主机 | 分布式同步工作节点 |

---

## 预期时间线

基于 100TB、7.01亿文件、单节点 200 线程：

| 阶段 | 预估时间 | 说明 |
|------|----------|------|
| 小批量测试 | 10-30 分钟 | 验证配置 |
| 全量迁移 | 10-15 天 | 单节点 200 线程，取决于网络带宽 |
| 失败重试 | 1-2 天 | 处理失败文件 |
| 抽样验证 | 4-8 小时 | 抽样 1 万个文件验证 |
| **总计** | **约 2 周** | 单节点模式 |

> **注意**：如果网络带宽或 COS 写入性能成为瓶颈，建议参考原方案扩展为 3 台机器并行。

---

## 性能优化建议

1. **如果带宽充足但 CPU 瓶颈**：可以适当增加 `--threads` 到 300
2. **如果列举文件慢**：增加 `--list-threads` 到 100
3. **如果需要限速**：使用 `--bwlimit` 限制带宽（如 `--bwlimit 1000` 表示 1000Mbps）
4. **如果需要分布式同步**：使用 `--worker` 参数扩展多节点并行

---

## 注意事项

1. **内存充足**：200 线程需要足够的内存支持，建议 64GB+
2. **文件描述符**：确保 `ulimit -n` 设置足够大（建议 65535）
3. **磁盘空间**：日志目录需要足够空间，建议定期清理
4. **网络稳定**：长时间运行确保网络稳定，避免频繁重连
5. **日志轮转**：大规模迁移日志会很大，建议配置日志轮转
6. **监控资源**：使用 `top`、`iostat`、`iftop` 等监控资源使用
7. **幂等性**：`--ignore-existing` 保证可重复执行，放心重跑
8. **缓存配置**：如需调整缓存，请通过目标端 `juicefs mount` 配置
9. **带宽限制**：内网环境可用 `--no-https`，外网建议使用默认 HTTPS
